Gatekeeper-RS

Automated Site Reliability & Infrastructure Monitoring Tool
Gatekeeper-RS คือเครื่องมือสำหรับเฝ้าระวังและกู้คืนระบบอัตโนมัติที่พัฒนาด้วยภาษา Rust ออกแบบมาเพื่อดูแลความเสถียรของ Infrastructure (เช่น API Services, Databases, Web Servers) โดยเน้นความรวดเร็ว ความปลอดภัย และการใช้งานที่ง่ายผ่านหน้าจอ Terminal

รายละเอียดโครงการ
โปรเจกต์นี้สร้างขึ้นเพื่อแก้ปัญหาการล่มของเซอร์วิสในระบบ Cloud และ Virtualization (Proxmox) โดยระบบจะทำหน้าที่เป็น "ผู้เฝ้าประตู" ที่คอยตรวจสอบสถานะและตัดสินใจสั่งซ่อมแซมระบบเบื้องต้นได้ทันทีโดยไม่ต้องรอเจ้าหน้าที่ดำเนินการ

คุณสมบัติหลัก
•	Interactive Configuration Wizard ระบบตั้งค่าผ่านหน้าจอ TUI ไม่ต้องแก้ไขไฟล์ .toml ด้วยมือ ลดความผิดพลาดและใช้งานสะดวก
•	Real-time Monitoring Dashboard หน้าจอแสดงผลสถานะระบบ พร้อมกราฟ Sparkline แสดง Latency และสถิติการใช้ Resource (CPU/RAM) ของเครื่อง Host
•	Automated Self-Healing ระบบกู้คืนอัตโนมัติที่สั่งรันคำสั่ง Restart ได้ทันทีเมื่อตรวจพบความผิดปกติ โดยใช้การรันโพรเซสแบบปลอดภัย (No Shell Injection)
•	Smart Alerting แจ้งเตือนเหตุการณ์สำคัญผ่าน Discord Webhook พร้อมระบบ Debounce ป้องกันการส่งข้อความซ้ำซ้อน
•	State-Transition Logging ระบบบันทึกเหตุการณ์ที่ชาญฉลาด บันทึกเฉพาะช่วงที่มีการเปลี่ยนแปลงสถานะเพื่อประหยัดพื้นที่จัดเก็บข้อมูล
•	Safety First รองรับโหมด Dry Run สำหรับทดสอบคำสั่งก่อนใช้งานจริง และระบบ Graceful Shutdown เพื่อการปิดโปรแกรมอย่างปลอดภัย

วิธีการติดตั้งและรัน
สิ่งที่ต้องมีในเครื่อง
•	Rust Toolchain (Cargo)
•	สิทธิ์การเข้าถึงเซอร์วิสที่ต้องการ Monitor (เช่น sudo สำหรับ systemctl)

การรันโปรแกรม
1.	ดาวน์โหลด Source Code และเข้าไปที่โฟลเดอร์โปรเจกต์
2.	เริ่มการตั้งค่าครั้งแรกผ่าน Wizard
     cargo run
3.	รันโปรแกรมในโหมดปกติเพื่อเริ่มการตรวจสอบ
     cargo run -- --config
4.	(ตัวเลือก) รันในโหมดทดสอบคำสั่ง (Dry Run)
     cargo run -- --dry-run

การใช้งานภายในหน้าจอ TUI
•	ปุ่ม R โหลดไฟล์ตั้งค่าใหม่ทันที (Hot Reload) โดยไม่ต้องปิดโปรแกรม
•	ปุ่ม Esc / Q ปิดโปรแกรมอย่างปลอดภัย
•	ปุ่ม Tab (ในหน้า Config) เปลี่ยนช่องกรอกข้อมูล
 
โครงสร้างไฟล์ที่สำคัญ
•	gatekeeper.log ไฟล์บันทึกเหตุการณ์สำคัญและการเปลี่ยนแปลงสถานะระบบ
•	config.toml ไฟล์ตั้งค่าหลักของระบบ (ถูกจัดการผ่าน Config Wizard)
•	testconfig.toml ไฟล์ตั้งค่าสำหรับทดสอบบนเครื่อง Local (จะถูกใช้งานก่อนไฟล์หลักถ้ามีอยู่)
